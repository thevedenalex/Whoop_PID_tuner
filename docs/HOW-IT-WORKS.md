# Что происходит под капотом

Как TinyWhoop PID Lab превращает `.bbl`-лог и список компонентов в готовый блок CLI-команд
для Betaflight. Документ для любопытных и для контрибьюторов: здесь описан каждый этап
конвейера, все факторы, влияющие на рекомендацию, и осознанные упрощения.

## Конвейер обработки

```
.bbl-файл
   │  1. Декодер (src/lib/bbl/parser.ts)
   ▼
Заголовки H (настройки, на которых записан лог) + поток фреймов I/P/S/G/H
   │  2. Маска чистого полёта (src/lib/analyze/metrics.ts)
   ▼
Сегменты «честного» полёта без стоянки на столе, посадок и столкновений
   │  3. Метрики по сегментам
   ▼
Перелёты, время установления, шум гироскопа, сатурация моторов, задержка отклика
   │  4. Движок тюна (src/lib/tune/engine.ts)
   ▼
Рекомендованные PID/фильтры/прочее + объяснения каждого изменения + CLI diff
```

Каждый этап независим: без лога движок работает от гоночной базы и каталога компонентов,
с логом — от фактических настроек в его заголовках.

## 1. Декодер Blackbox

Собственная реализация протокола **Blackbox Data Version 2** (Betaflight 4.4–4.5),
никаких серверов — файл разбирается целиком в браузере:

- H-фреймы: словарь `ключ:значение` — отсюда читаются PID, фильтры, TPA, рейты,
  версию прошивки, полевой список и предикторы.
- I/P-фреймы: gyroADC, setpoint, rcCommand, motor[], vbat и прочие поля. Поддержаны
  все типы кодирования (tag8/field-заголовки), предикторы (0/1/2/4/5/6/7/8/9/10/11)
  и развёртка переполнения `time`.
- В файле может быть несколько логов (сессий). Приложение **автоматически выбирает
  самый информативный** (максимум фреймов gyroADC) и позволяет переключаться вручную —
  это решение проблемы «загрузил лог, а он пустой».

## 2. Маска чистого полёта

Не вся запись одинаково полезна. Метрики считаются **только по сегментам чистого полёта**;
исключённые участки видны на графиках серым. Критерии исключения:

- **Стоянка на столе** — газ ниже порога и почти нет движения стиков.
- **Посадки** — длительные просадки газа в ноль между полётными сегментами.
- **Столкновения / нештатные ситуации** — пики на gyroADC, многократные переполнения
  моторов, «подпрыгивание» setpoint-ошибки. Также отдельно исключаются кадры активных
  манёвров (большой стик или быстрое вращение) из оценок **шума** — иначе полезный сигнал
  маскировался бы под шум.

## 3. Метрики полёта

По осям roll/pitch/yaw (по сегментам чистого полёта):

- **Overshoot, %** — насколько гироскоп «перелетает» сетпоинт при резких командах.
  Целевой диапазон 2–12%: меньше — заниженные P/D (вялый), больше — не хватает D.
- **Settle time, мс** — время установления после ступеньки; долгое «звенение» = не хватает D.
- **Шум gyroADC, °/с** — RMS в покое (hover) и на полном газе; их отношение
  показывает, сколько шума вносит дроссель (моторы/пропы) против внешних вибраций.
- **Сатурация моторов, %** — доля времени у 100% throttle (упор в потолок тяги).
- **Задержка отклика, мс** — между командой и реакцией гироскопа.
- **Смещение I-term в ховере** — перекос центра тяжести или заводской крена.
- **Итоговая оценка 0–100** — штрафы за перелёт, раскачку, шум, сатурацию, задержку.

## 4. Движок тюна

### Стартовая точка

- **Без лога** — гоночная база класса (`BASE_65` / `BASE_75`): PID, минимально
  необходимые фильтры (gyro lpf1 = 0, PT1, dyn-notch ×3 Q4.5), TPA выключен,
  iterm_relax = setpoint.
- **С логом** — **фактические настройки из H-заголовков лога**. Приложение меняет
  только то, что реально улучшит поведение; CLI-дифф выводит **только отличающиеся**
  от лога параметры — можно вставить блок целиком, уже летавшее останется нетронутым.

### Факторы, влияющие на рекомендацию

| Фактор | Как влияет |
|---|---|
| **Взлётный вес (AUW)** | Отклонение от референса класса (26 г / 34 г) каждые полные 5 г: P ±2, I ±6, D ±2. Тяжелее — больше авторитета; легче — меньше нагрев. При +8 г — предупреждение о просадках. |
| **Класс рамы 65/75 мм** | Своя база PID и фильтров: 75 мм чуть выше P/I и ниже частоты среза. |
| **Жёсткость рамы** | Карбоновый усилитель → D +1, gyro_lpf2 +10 Гц: рама прогибается меньше, пропвош и резонансы слабее — можно больше демпфирования и чуть слабее фильтры. |
| **KV моторов** | ≥24000 → D −2 (нагрев D-члена от шума). ≥28000 → ещё D −2 и предупреждение о нагреве. |
| **Подшипники моторов** | Шариковые (ball) → D +1: меньше механического шума и люфтов. |
| **Число лопастей пропов** | 4 лопасти → D −1, gyro_lpf2 −30 Гц, нотчей минимум 4. 2 лопасти → D +1, gyro_lpf2 +20 Гц. 3 лопасти — нейтрально. |
| **Характер шага пропов** | Агрессивный → D +1, gyro_lpf2 −10 (тяга ценой шума). Лёгкий → P +1, gyro_lpf2 +10 (меньше тяги — добираем резкость P). |
| **Тип гироскопа FC** | ICM-42688P (самый чистый сигнал) → gyro_lpf2 +20. BMI270 → потолок 290 Гц. MPU6000 (самый шумный) → потолок 250 Гц. |
| **Рейты (actual)** | Roll/pitch ≥800°/с → iterm_relax_cutoff 12 (быстрее отпускаем I). ≤600°/с — предупреждение «будет вялым». Yaw ≤500°/с — предупреждение. |
| **Профиль резкости** | «Мягкий»: P −3/−3/−2, D −2, фильтры жёстче, FF boost 0. «Гоночный»: базовые пороги. «Максимум»: P +3/+3/+4, FF boost 10, при чистом логе D +3, gyro_lpf2 +30, нотчи ×2. |

### Коррекции по логу (поверх всего выше)

Пороги зависят от профиля резкости — «мягкий» терпит больше перелёта, «максимум»
требует жёстких стопов и раньше добавляет P/D.

- **Перелёт** сильный → D +4..6, P −1..2; умеренный → D +2..3; перелёта почти нет и
  шум низкий → P +2..5, D +2..4 (можно резче).
- **Раскачка** (settle > 110–160 мс) → D +3.
- **Шум на газе** высокий → gyro_lpf2 ≤250, нотчи ×4, dterm dyn ≤100, D −2; шум низкий →
  ослабляем фильтры до целевого уровня (выключенный lpf2 обратно **не включаем** —
  минимальная задержка важнее).
- **Сатурация моторов** >3% → TPA 55% @1650 (если в логе TPA уже был — сохраняем
  выбор пилота и предупреждаем).
- **I-term в ховере** перекошен → I +8 и совет проверить центровку.
- **Yaw перелетает** → P yaw −3.

### Оценка задержки фильтров

Для каждого набора фильтров считается групповая задержка (мс): PT1 — `1/(2π·fc)`,
динамический нотч — `Q/(π·f0)` на центре диапазона, BIQUAD ≈ ×1.9 от PT1.
Показываем: текущая задержка, базовая, отклонение и задержка фильтров, реально
летавших при записи лога. Цель гоночного тюна — удерживать суммарную задержку
пути «гироскоп + D-term» в минимуме без вылета в шум.

### CLI diff

Блок команд `set ... = ...` + `save`. При загруженном логе — только отличающиеся
от настроек лога параметры; тип фильтра не эмитим, если сам фильтр выключен
(частота 0). Имена переменных сверены с исходниками Betaflight 4.4–4.5
(`tpa_rate` в процентах 0–100, `anti_gravity_gain`, `dyn_notch_q` ×100 и т.д.).

## Осознанные упрощения и ограничения

- **Камеры, VTX, приёмники, канопы, АКБ** влияют только через вес (разделение 1S/2S —
  для удобства группировки списка). Видеосистема на PID влияет мало, но вес цифровых
  HDZero-компонентов ощутим — он и учитывается. Жёсткость рамы учитывается только
  для позиций с карбоновым усилителем; тонкие PP-рамы без усилителя считаются
  стандартными.
- **Пропавшая партия гироскопов**: Happymodel Diamond/X12 выпускались с MPU6000,
  ICM20689 или BMI270 — у этих плат гироскоп не задан, влияние не применяется.
- **Оценки шума/перелёта** — эвристики на RMS и порогах, а не модель системы;
  в спорных случаях приложение объясняет, откуда взялась цифра, и предлагает
  итеративный подход: «летай → лог → тюн → повтор».
- **Референсные веса** компонентов — ориентировочные (по спецификациям
  производителей); точный вес своей сборки можно подогнать полем «Прочее», г
  (допускает отрицательные значения — после облегчения рамы/проводов).

## Разработка

```bash
cd app
npm install
npm run dev     # дев-сервер
npm run build   # прод-сборка (tsc + vite)
npm test        # тесты движка тюна (vitest)
npm run test:logs  # проверка на реальных .bbl из ../testlogs
```

Логика движка покрыта тестами (`app/verify-engine.test.ts`): базы классов, поправка
на вес, KV-моторы, влияние пропеллеров (лопасти/шаг), гироскопы FC, покрытие
объяснений. При изменении порогов или каталога тесты должны оставаться зелёными.
